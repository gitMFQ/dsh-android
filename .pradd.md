### Two defects CI caught that this box could not

This box cannot compile `:app`'s test sources (`docs/BUILD-AND-CI.md` §0 — aapt2), so
the first push went out with `SystemBarsTest` unverified. It failed, and it was right:

1. **`SystemBars` had the flag inverted.** `isAppearanceLightStatusBars = true` means
   *"this bar is light, so draw dark icons"* — it describes the **background**, not the
   icons. I read it as "the icons are light" and negated the palette, which reproduced
   the exact bug the class exists to fix, just in the other direction. Renamed to
   `lightBackground` so the meaning is in the name, and the six assertions now state the
   direction per appearance instead of implying it.
2. **`build.yml` was still on JDK 17.** 2.4 moved the palette adapter into `:design`,
   which put miuix's Java 21 bytecode on *that* module's test classpath. The Debug APK
   job then died with `NoClassDefFoundError` inside `:design:testDebugUnitTest` — 25
   tests failing at once, which reads like a broken test file and is actually a JDK
   version. Raised to 21, matching `verify.yml` / `screenshots.yml`. `release.yml` stays
   on 17 on purpose and now says why: it only assembles, and D8 handles the bytecode.

Both are recorded where the next person will hit them rather than only here.
