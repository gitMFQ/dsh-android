# 多语言（i18n）系统规划

> 现状实测（`/tmp/dsh-android-prior`）：`res/values/strings.xml` 只有 **6 条字符串**，**全仓 `stringResource(` 调用 = 0**，所有界面文案都是 Kotlin 里的硬编码英文。
> 结论：**这不是「加几种语言」的问题，是一次彻底的字符串外化工程。**

## 1. 现状债务量化

| 区域 | 用户可见英文字面量 | 说明 |
|---|---|---|
| `ui/`（根目录 18 个文件） | 约 **807** | ChatScreen / SessionsDrawer / Sheets / About 等，最密集 |
| `ui/components/` | 约 **323** | 工具卡片、输入框、文件面板 |
| `widget/` | 21 | 桌面小组件文案（`WidgetText` 里是「规则」而非可翻译短语） |
| `ui/search` / `ui/settings` / `ui/markdown` | 9 / 5 / 2 | 少量 |
| `model/` | 186 | **大部分不是 UI 文案**（协议键名、日志），需逐个甄别 |
| `net/` | 61 | 同上，多为错误码 |

**粗估需要外化的用户可见字符串：约 1 000–1 200 条**（扣掉协议键、日志、测试串后）。
> 按每文件平均 30 条、每天 3–4 个文件算，**单人大约 2 周**。i18n 是独立工作流，不是顺手活。

## 2. 语言集与优先级

DSH 上游支持 **8 种语言**：`de, en, es, fr, ja, pt, ru, zh`（263 个包各自带 `locale/<lang>.json`）。建议**与上游对齐同一套**：术语一致、翻译记忆可复用。

| 档 | 语言 | 依据 |
|---|---|---|
| **P0** | `zh`（简体中文）、`en` | 你的使用场景 + 默认 |
| **P1** | `ja`、`ru` | DSH 社区活跃语种 |
| **P2** | `de`、`es`、`fr`、`pt` | 机器翻译 + 抽检 |

> 首版（v1.0）**只交付 zh + en**；其余在建好工作流后批量补。文案还在改的时候翻译是纯浪费。

## 4. 技术方案

### 4.1 资源布局

```
res/
  values/strings.xml            # 默认 = 英语（en 是 fallback）
  values-zh-rCN/strings.xml     # 简体中文
  values-ja/strings.xml
  values-de/ ...
```

- **默认 `values/` 放英语**（不是中文）：Android 约定，避免英文设备出现中文兜底。
- 用 `values-zh-rCN`（简中）；要繁体再加 `values-zh-rTW`。
- 复数用 `<plurals>`（英文 `1 session` vs `2 sessions`；中文虽无复数也要声明）。
- 带格式化的串一律 `%1$s` / `%2$d`；非文案项加 `translatable="false"`。

### 4.2 Compose 使用

```kotlin
Text(stringResource(R.string.session_new))
Text(stringResource(R.string.session_count, n))
Text(pluralStringResource(R.plurals.sessions, n, n))
```

- **禁止拼接**：`"共 " + n + " 个会话"` 在 8 种语言里语序全错，必须用占位符。
- 长文案（设置项副标题）单独命名，不要复用同一个串。

### 4.3 应用内语言切换（关键难点）

| 方案 | API 覆盖 | 说明 |
|---|---|---|
| **`AppCompatDelegate.setApplicationLocales()`** | 33 原生；21–32 由 appcompat backport | **推荐**：一套代码全版本可用，系统设置里也出现「应用语言」入口 |
| `LocaleManager` | 33+ | 原生，低版本要自己兼容 |
| 自管 `Resources.updateConfiguration` | 全版本但不推荐 | 已废弃、易漏、需重建 Activity |

> fork 是纯 Compose、无 appcompat。**引入 `androidx.appcompat`（只为 language backport）**或直接用 `androidx.core` 的 `LocaleManagerCompat`。落地时在 API 26 真机验证一次。

### 4.4 不需要翻译但要处理的部分

| 项 | 处理 |
|---|---|
| `contentDescription`（无障碍） | **要翻译**（视障用户也读界面语言） |
| 日志 / 异常消息 | 不翻译，保持英文（便于检索 issue） |
| 协议键名 / 工具名（`bash`、`read`…） | 不翻译；显示时可加中文副标题 |
| 服务端返回内容（agent 输出） | **不归我们控制**：语言由提示词与模型决定 |
| 时间 / 数字 | 用 `DateTimeFormatter.ofLocalizedDateTime` 与 `NumberFormat`，不要手写 `HH:mm` |
| 字体 | 中文用系统默认（Noto）；日语需确认 `values-ja` 下字体回退正常 |

## 5. 抽取计划（不动测试的前提下）

| 步 | 内容 | 验收 |
|---|---|---|
| **I1** | 建 `strings.xml` 骨架 + 引入语言 API + 设置页加「语言」项 | 切换语言后 App 进英文/中文 |
| **I2** | 先抽 `SettingsContent.kt` + `AboutScreen.kt`（文案集中、风险低） | 两页 100% 走 `stringResource` |
| **I3** | 抽 `SessionsDrawer.kt` | 抽屉全量 |
| **I4** | 抽 `ChatScreen.kt` + `Sheets.kt`（最大头） | 聊天页 + 11 个 Sheet 全量 |
| **I5** | 抽 `ui/components/**`（工具卡片 323 条） | 全量 |
| **I6** | 补齐 zh 翻译 + 抽检 | 中文界面无残留英文（除协议键） |

**每步都跑 1 116 个测试**。字符串外化天然安全（不改逻辑），但**截图测试会因文案变化漂移** → 先给测试**强制指定 locale**（`@Config(qualifiers = "en")`）再抽。

## 6. 防止回退：CI 门禁

```yaml
- name: no hardcoded UI strings
  run: |
    ! grep -rnE 'Text\("[A-Z]' --include=*.kt app/src/main/java/uk/xa0/dsh/ui
```

> 更严谨可用自定义 Detekt 规则，但 grep 门禁 5 分钟就能上线，**先用 grep**。

## 7. 翻译工作流（8 语言的长期维护）

| 选项 | 成本 | 适合 |
|---|---|---|
| **Weblate 自托管** | 免费，需一台 VPS | **推荐**：Android strings.xml 原生支持，带翻译记忆与审校 |
| Crowdin / Lokalise | 付费 | 有预算、要术语库强制 |
| 机器翻译（DeepL/LLM）+ 人工抽检 | 近零 | P2 语言可接受 |

**流程**：`values/strings.xml`（en）为唯一真源 → Weblate 拉取 → 各语言译者/机翻 → PR 回 `values-<lang>/` → CI 校验。

**CI 必查三项**：① 无多余 key（翻译文件里存在但 `values/` 里没有）；② 每条的 `%1$s` 占位符数量与原文一致；③ `translatable="false"` 的条目未被翻译。

## 8. 与里程碑的衔接

| 阶段 | i18n 状态 |
|---|---|
| 阶段 0–1（接管 + 结构） | 只建骨架（I1），不做抽取 |
| 阶段 2（外壳换装） | **换装时顺手把该文件抽干净**（I2–I3），避免二次返工 |
| 阶段 3（聊天精修） | 抽 ChatScreen / Sheets（I4–I5） |
| 阶段 4（发布） | 补齐 zh + en（I6），其余语言 post-1.0 |

> **顺序原则**：换哪个文件就抽哪个文件，不要「先全换皮再统一抽字符串」——那是同一批文件改两遍。
